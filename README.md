# robox-iot
基于MQTT + SpringBoot + MQTTX + EMQX的机器开舱与设备上报机器状态。

上行：
设备 -> MQTT -> EMQX -> Spring Boot

下行：
HTTP -> Spring Boot -> MQTT -> EMQX -> 设备

完整：
设备上报 -> 服务端处理 -> 指令下发 -> 设备执行 -> 结果回执

# 1.什么是物联网

1.物联网，英文名 **iot**。

2.在计算机网络的概念里面，**物联网其实就是各种物理设备通过通信网络与服务器进行连接**，从而进行应用。

# 2.为什么MQTT

1.因为它的**报文小**、**保持TCP长连接**、**发布/订阅模型**、**支持不稳定网络**、**容易处理大量设备。**

2.并且在实际应用场景下，比如温度传感器，它不太依赖服务器的完整响应，而是比如说设备上传了数据，在服务器端可以给其他微服务使用。

3.而对于语言的选择，比如Java、python、c，其实它们三个可以配合，比如说业务是由Java做的，比如订单、支付、开舱，**需要和其他微服务进行交互的**，最好用Java，因为天然的SpringCloud好管理，适合生态，说白了就是**云端业务**。python其实是集成了一些硬件功能，比如钩爪控制、语音识别、人脸识别，这种情况它更适用。c就是最最底层的，操控硬件。

4.所以 Java + iot的岗位其实就是 **物联网的云端业务开发**，多了一层，**以MQTT协议接入设备这一层**。

# 3.什么是MQTT

1.MQTT是一种基于 发布/订阅者 模型的 通信协议。

2.MQTT Broker是实现了MQTT通讯协议的代理软件，能够接收并转发MQTT消息。

3.所以自然而然的，我们就要**部署实现了MQTT协议的代理软件**。

# 4.为啥MQTT Broker不用Kafka

因为MQTT Broker和Kafka用的不是一个协议，Kafka用的自己的协议。

# 7.报文类型


1.报文格式：

- **固定报头** + **可变报头** + **有效载荷**

2.**固定报头在所有报文类型中**，但是可变报头和有效载荷是否存在和内容**取决于具体的报文类型**。


3.可变报头：不同的报文的内容不一样，但是它们都有Properties，属性值。

给 MQTT 报文附加的一些“**元数据** / 控制参数”，用来告诉对方：这条消息应该怎么处理。


# 8.QOS

1.QOS是消息质量等级，在发送消息的时候指定的消息质量等级。

QOS = 0：消息最多发1次，不重试、不确认。考虑消息丢失问题。

QOS = 1：消息至少发1次，发送方会受到一次确认报文。考虑重复消费问题，服务端需做幂等。

QOS = 2：消息一定只发1次，不断重复确认。开销大。
